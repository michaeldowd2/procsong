How to make a procsong…

A procsong is a zip of audio clips plus a definition.yml. The same zip and seed always produce the same arrangement: tracks of different lengths overlap and recombine, so the piece keeps going without a fixed loop.

  1. Record a few interchangeable clips per track (e.g. two drum loops). Make each wav a couple of seconds longer than the start interval so tails overlap.
  2. Put them in folders named after the track, and write a definition.yml next to those folders.
  3. Zip the yaml and the clip folders together, host the zip, then add its URL to a library.

Minimal definition.yml — one drums track that picks a clip every 8 seconds:

Drums:
  type: primary
  part_duration: 8
  repeats: 4
  probability_silence: 0
  parts:
    - Drums/A.wav
    - Drums/B.wav

part_duration is when the next clip starts, not how long the wav is. repeats is how many starts of that same choice before a new clip is picked. Tracks do not share a bar: a 15-second track can restart while a 20-second track is still on its first clip. Mute is volume after a choice — other tracks still see the chosen part. The exact algorithm (clocks, evaluation order, shared PRNG) is SPECIFICATION.md. Add more tracks as secondary or standard if they should follow whatever drums (or other tracks) chose.

Make my own library and share with others…

A library is a CSV or JSON file of procsong packages. Host it anywhere the browser can fetch (a Dropbox share link works), paste that URL above, and press Load. The address bar updates with library_url so you can send this page to friends.

Only procsong_url is required. Everything else is optional:

  • title, artist, description
  • tags — semicolon-separated, e.g. game music;synth
  • procsong_url — zip of the procsong package
  • image_url — cover art
title,artist,description,tags,procsong_url,image_url
"Game Music","Michael Dowd","A procedural song","game music;synth","https://…/song.zip","https://…/cover.png"

JSON is an array of objects with the same field names.
